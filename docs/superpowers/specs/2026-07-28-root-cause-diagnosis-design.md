# Root-Cause Diagnosis + Tiered Action Plan — Design Spec

Date: 2026-07-28
Status: Approved for planning

## Problem

The Level-1 tool produces a scored list of *findings*, each with a single
`recommendation` string. When pointed at a real recurring-crash machine it
correctly surfaces the symptoms ("9 unexpected shutdowns, no bugcheck") but it
does **not** do what a human debugger does: synthesize the signals into a
**root-cause verdict**, state what has been **ruled out**, and hand back a
**prioritized, tiered action plan**. The user wants that analysis to live *in
the report*, generated by the tool itself.

## Goals

1. Add a synthesized **Primary Diagnosis** to the report: root cause +
   confidence, what's happening, timing pattern, ruled-out reasoning, and a
   Tier 1/2/3 action plan.
2. Collect the extra signals that make the diagnosis defensible: true crash
   times (load-hours pattern), memory speed/EXPO state, Event 41 sleep/power
   flags, thermal throttle events, and — opt-in — real hardware sensors
   (temps, fan RPM, rail voltages, SPD/EXPO).
3. Cover both crash signatures: instant power-loss/hard-hang **and** software
   BSOD, plus thermal.

## Non-Goals / Constraints

- **Deterministic only.** No LLM, no network calls. Same reasoning inputs →
  same report.
- **On-demand, read-only.** The tool observes; it never changes configuration.
- **Zero-dependency baseline stays intact.** `python diagnose.py` with no flags
  loads no kernel driver and needs no new runtime beyond today's.
- Direct PSU telemetry (digital-PSU vendor SDKs) is out of scope. We read
  motherboard **12V rail sag** as the PSU proxy, only under `--sensors`.
- Precise EXPO/SPD is best-effort: WMI heuristic in the baseline, true SPD read
  only under `--sensors` when the sensor DLL exposes it.

## Architecture Overview

Unchanged pipeline shape: collectors (PowerShell/optional sensor) → normalize →
`Timeline` → rules (findings) **+ synthesizers (diagnoses)** → report (HTML +
JSON). Two additions: a **synthesis layer** that runs after rules, and new
**collectors**. Scoring is unchanged — diagnoses are presentational.

### 1. Data model (`pcdiag/models.py`)

- `CrashEvent` gains optional fields (default `None`, backward compatible):
  `actual_when: datetime | None`, `actual_local_hour: int | None`,
  `sleep_in_progress: int | None`, `power_button: int | None`.
- `MemoryConfig` (new): `dimm_count`, `rated_mts`, `configured_mts`,
  `part_number`, `overclocked: bool | None`. → `Timeline.memory_config`.
- `ThermalEvent` (new): `when`, `kind` (throttle/critical), `source`, `detail`.
  → `Timeline.thermal_events`.
- `SensorReading` (new): `name`, `kind` (temp/fan/voltage/clock), `value`,
  `unit`, `min`, `max`. → `Timeline.sensors` (empty unless `--sensors`).
- `ActionStep` (new): `tier` (1|2|3), `title`, `detail`, `effort`
  ("free"/"10 min"/"isolation"), `rationale`.
- `Diagnosis` (new): `id`, `title`, `root_cause`, `confidence` (reuse
  `Confidence`), `severity` (reuse `Severity`), `whats_happening`,
  `timing: str | None`, `ruled_out: list[str]`, `action_plan: list[ActionStep]`,
  `supporting_finding_ids: list[str]`.

### 2. Collectors

Baseline (always run, pure PowerShell/WMI):

- **`crashes.ps1` (expand):** for each Event 41, read `[xml]$e.ToXml()`
  EventData for `BugcheckCode`, `PowerButtonTimestamp`, `SleepInProgress`. For
  each Event 6008, read raw inserted strings (`$e.Properties[0]` = time,
  `[1]` = date) and combine via `Get-Date` (respects local culture, avoids
  fragile sentence regex) → emit `actual_when` (UTC ISO) **and**
  `actual_local_hour` (0–23 local). Event 1001 bugcheck parsing stays.
- **`memory_config.ps1` (new):** `Win32_PhysicalMemory` → `dimm_count`, rated
  `Speed`, `ConfiguredClockSpeed`, `PartNumber`. Heuristic:
  `overclocked = configured_mts > 5600` (DDR5 JEDEC ceiling); "not overclocked"
  asserted only when `configured_mts <= rated_mts`.
- **`thermal.ps1` (new):** thermal-throttle / critical events
  (`Microsoft-Windows-Kernel-Processor-Power` 86/87/88; ACPI thermal-zone
  events) over the crash window; plus best-effort `MSAcpi_ThermalZoneTemperature`
  (root\WMI). Honestly emits empty temps when the platform exposes none.

Opt-in deep sensors (`--sensors`, only if the DLL is present):

- **`sensors` collector:** loads `LibreHardwareMonitorLib.dll` from `tools/`
  via PowerShell `Add-Type` and reads temps (CPU/GPU/VRM), fan RPM, voltages
  (Vcore, VSOC, +12V, +5V, +3.3V), and SPD/EXPO where exposed. If the DLL is
  absent or the flag is off, the collector is **skipped** with a `meta` note —
  never an error. Requires admin (driver load); degrades to baseline otherwise.

Registration: add `memory_config`, `thermal` to `COLLECTOR_NAMES` and
`NORMALIZERS`; `sensors` is appended conditionally by `diagnose.py` when
`--sensors` is passed.

### 3. Synthesis layer (`pcdiag/synthesize.py`)

A `SYNTHESIZERS` registry mirroring `RULES`.
`run_synthesis(timeline, findings, config) -> list[Diagnosis]` runs each,
collects non-`None` results, sorts by `severity.weight * confidence.multiplier`
(same ranking as findings). The top diagnosis renders as the **hero**; any
others render as compact secondary diagnosis cards.

Synthesizers (priority by the sort, not order):

- **`_synthesize_software_bsod`** — trigger: any bugcheck code present or a
  minidump exists. Classifies the bugcheck family and tailors root cause + tiers:
  - `0x9F` DRIVER_POWER_STATE_FAILURE → a driver stalls power transitions
    (sleep/wake); correlate with recent driver changes.
  - `0x116/0x117` → GPU TDR / display-driver timeout.
  - `0x1A/0x50/0x4E/0x1E` → memory/kernel-memory.
  - `0xD1` → driver IRQL_NOT_LESS_OR_EQUAL.
  - default → generic bugcheck with dump-analysis guidance (WinDbg `!analyze`).
  Correlates the newest matching driver/change before onset for the "suspect".
- **`_synthesize_power_loss`** — trigger: unexpected-shutdown finding present
  **and** no bugcheck **and** no dump (instant power-loss signature).
  - root cause: "Instant power loss / hard-hang under load — likely
    PSU/power-delivery or GPU transient."
  - `timing`: bucket `actual_local_hour` into morning (6–12), afternoon (12–17),
    evening (17–22), night (22–6). Emit the line only when ≥60% fall in
    evening+night ("clusters in active/GPU-load hours, not at boot/idle").
  - `ruled_out`: conditional lines — software BSOD (no bugcheck/dump); WHEA (if
    none); TDR (if no display resets); **RAM** (no memory bugchecks/WHEA/failed
    diag; append "at rated speed, not overclocked" when `memory_config` supports
    it); **sleep** (no crashes with `SleepInProgress`).
  - Sensor enrichment when `--sensors` data present: 12V rail sag or high
    VRM/CPU temp under load is added as supporting evidence, raising confidence.
  - `action_plan`:
    - Tier 1 (free/software): reset GPU tuning to default; uninstall AMD Ryzen
      Master / tuning tools **only if such a change is detected**; DDU + clean
      GPU driver reinstall; update motherboard BIOS/AGESA.
    - Tier 2 (10 min/cables): reseat 24-pin/EPS/GPU power; run the GPU on **two
      separate PCIe cables** (no daisy-chain); note PSU make/wattage/age.
    - Tier 3 (isolation): cap GPU power ~15–20% / frame cap; **iGPU-only test —
      only if an integrated GPU is detected** in the snapshot; OCCT Power test
      to reproduce on demand.
    - GPU-specific steps included only when a discrete GPU is present.
- **`_synthesize_thermal`** — trigger: thermal-throttle/critical events present,
  or a sensor temp over threshold (CPU ≥ 95 °C / GPU ≥ 100 °C). Root cause:
  thermal shutdown/throttle; tiers: clean dust/airflow, reseat cooler/repaste,
  check fan curves, verify VRM cooling on the mATX board.

Priority when multiple apply: a real bugcheck (software BSOD) and power-loss are
mutually exclusive by construction (bugcheck presence). Thermal can co-occur and
will rank by its own severity/confidence, appearing as hero if it outranks the
others, else as a secondary card.

### 4. Report (`pcdiag/report.py` + `templates/report.html.j2`)

- `render_report` also accepts `diagnoses: list[Diagnosis]`.
- JSON adds `"diagnoses": [...]` (each with nested `action_plan`).
- Template: a **Primary Diagnosis** hero card above "Issues" (guarded by
  `{% if diagnoses %}`) showing title, confidence badge, "What's happening",
  "Timing" (if any), a "Ruled out" list, and the action plan grouped by tier
  with each step's effort + rationale. Secondary diagnoses render as compact
  cards. A best-effort **Sensors** table renders when `timeline.sensors` is
  non-empty. Finding cards and the change timeline stay below, unchanged.
- `pipeline.run_pipeline` calls `run_synthesis` and passes `diagnoses` through.

### 5. CLI (`diagnose.py`)

- Add `--sensors` (opt-in deep hardware read; appends the `sensors` collector).
- Behavior unchanged without the flag. Print a one-line note when `--sensors` is
  requested but the DLL is absent ("deep sensors unavailable; using baseline").

## Testing

- **`test_synthesize.py` (new):**
  - Power-loss fixture (KP-41 ×N, no bugcheck/dump, evening-clustered
    `actual_local_hour`, memory not overclocked) → asserts root cause,
    ruled-out set (software+RAM+sleep), three tiers, iGPU step gated on the
    snapshot, Ryzen-Master step gated on a detected change.
  - Bugcheck fixture (`0x9F` + dump) → software-BSOD diagnosis with the
    DRIVER_POWER_STATE_FAILURE narrative and driver correlation; power-loss
    synthesizer returns `None`.
  - Thermal fixture (throttle events) → thermal diagnosis present.
  - Timing line omitted when < 60% load-hours.
  - No crashes → empty list.
- **`test_normalize.py` (extend):** 6008 pairing → `actual_when` +
  `actual_local_hour`; Event 41 sleep/power flags; `memory_config`;
  `thermal_events`; `sensors` (from a stubbed collector payload).
- **`test_report.py` (extend):** hero renders when diagnoses present, absent
  when empty; secondary cards; sensors table gated on data.
- **Sensor collector:** unit-test the "DLL absent → skipped with meta note, no
  exception" path (no driver load in CI). All existing tests stay green.

## Rollout / Backward Compatibility

New model fields are optional with defaults; new `Timeline` fields default to
empty. Existing rules, findings, and score are untouched. Report JSON is
additive (`diagnoses`, sensors). Baseline run needs no new dependencies; only
`--sensors` requires `LibreHardwareMonitorLib.dll` in `tools/` and admin.
